# container-image-layer-analyzer-java

针对**本地**容器镜像的分层体积分析与冗余内容优化工具。输入是磁盘上已经导出的
镜像归档（`docker save` / OCI layout 的 tar、tar.gz）或展开后的镜像目录，
整个过程不依赖任何外部服务。

## 功能概览

- 按层与整镜像输出体积报告，条目区分：普通文件、目录、符号链接、硬链接、
  删除标记（whiteout）、不透明目录标记、其他。
- 正确还原 overlay 叠加语义，给出最终文件系统体积与可回收空间。
- 流式处理，内存占用有明确上界且可配置；扫描期间可查询实时进度。
- 相同输入在任意并发度下产出逐字节一致的报告。
- 损坏输入按层给出可区分的失败原因，不静默通过，不留下部分写入的产物。
- 多任务共享执行资源，层粒度轮转调度，支持取消与超时。
- 产出清理冗余后的优化镜像（docker save 布局目录），其叠加后的最终文件系统
  与原镜像等价。

## 叠加语义

分析器按层序（从底层到顶层）应用每个 tar 条目，规则如下：

1. **覆盖**：后层同路径条目覆盖先层。目录被非目录条目替换时，其整个子树失效。
2. **删除标记（whiteout）**：`<dir>/.wh.<name>` 隐藏**更低层**的 `<dir>/<name>`
   及其子树；同层条目不受影响（同层文件胜出）。标记自身不进入最终文件系统。
3. **不透明目录标记**：`<dir>/.wh..wh..opq` 隐藏 `<dir>` 下所有来自更低层的条目，
   同层及更高层条目不受影响。
4. **硬链接**：引用同镜像内已存在路径的内容。内容按 inode 引用计数：
   目标被删除后，只要仍有硬链接引用，内容字节就计入最终文件系统；
   最后一个引用消失时，内容字节计入可回收。

## 体积口径

- **层体积 / 条目字节**：只统计普通文件的**内容字节**（tar 头、对齐填充、
  目录/链接等元数据不计入）。
- **最终文件系统体积**：被至少一个最终路径引用的 inode 内容字节之和
  （硬链接共享的内容只计一次）。
- **可回收字节数** = 被后层覆盖/被删除标记隐藏的内容字节
  + 删除/不透明标记自身字节（通常为 0）
  + 同层重复内容的多余拷贝（可改写为硬链接回收）。
  可回收量按"产生浪费的层"与"路径"归因，报告给出主要贡献层与主要贡献路径。
- **报告确定性**：字段顺序固定、Map 按键排序、贡献者列表按
  （字节数降序，键字典序升序）排序；相同输入的报告逐字节一致。

## 优化产物等价性

优化器只保留"存活"条目：最终文件系统的胜出条目 + 内容仍被（硬链接）引用的
原始条目；效果涉及保留条目的删除/不透明标记一并保留；同层重复内容改写为
硬链接；目标已失效的硬链接物化为普通文件（内容经临时 spill 文件转写）。
因此优化产物叠加后的最终文件系统与原镜像**逐路径等价**（内容、类型一致；
去重后的硬链接与源文件共享 inode，属正常文件系统语义）。

产物先写入 `<output>` 同级的 `.optimize-*` 临时目录，完成后原子落位；
失败或取消时临时目录被清理，不残留中间产物。输出路径已存在时拒绝执行。

## 内存上界

- 单层扫描/重写只使用一个 `analyzer.io-buffer-bytes` 大小的缓冲区，
  文件内容以流式 SHA-256 计算，**绝不把整层或整个镜像读入内存**。
- 元数据内存与最终文件系统条目数成正比（叠加状态、层内内容索引）。
- 镜像归档输入先流式解包到临时目录（固定缓冲），关闭时清理。

## 任务调度

- 所有任务共享 `analyzer.worker-threads` 个执行线程；调度以"一层"为分片
  在就绪任务间轮转（round-robin），单个超大任务不会长期饿死其他任务。
- 取消与超时在条目级与分片级检查点生效，触发后立即中止会话、关闭输入、
  清理临时产物。
- 任务状态可区分：`PENDING / RUNNING / SUCCEEDED / FAILED / CANCELLED / TIMEOUT`。

## 配置项（application.properties）

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `analyzer.io-buffer-bytes` | 65536 | 流式读缓冲区大小（单层内存上界的主要来源） |
| `analyzer.max-path-length` | 4096 | 条目路径最大长度，超出记为非法元数据 |
| `analyzer.worker-threads` | CPU/2 | 执行线程数（所有任务共享） |
| `analyzer.task-timeout-millis` | 600000 | 单任务超时（毫秒），<=0 不限制 |
| `analyzer.top-contributors` | 20 | 报告主要贡献者条数上限 |

## REST API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/tasks/scan?input=<path>` | 提交扫描任务 |
| POST | `/api/tasks/optimize?input=<path>&output=<path>` | 提交优化任务 |
| GET | `/api/tasks` | 列出任务（含实时进度） |
| GET | `/api/tasks/{id}` | 查询任务状态与进度 |
| GET | `/api/tasks/{id}/report` | 获取体积报告（SUCCEEDED 后） |
| GET | `/api/tasks/{id}/optimize-result` | 获取优化结果（SUCCEEDED 后） |
| DELETE | `/api/tasks/{id}` | 取消任务 |

## 错误口径

层级错误按原因区分：`TRUNCATED_ARCHIVE`（截断/缺少结束标记）、
`CHECKSUM_MISMATCH`（头校验失败）、`PATH_TRAVERSAL`（`..` 或驱动器号绝对路径）、
`INVALID_METADATA`（空名/NUL/超长路径等）、`IO_ERROR`。
非法元数据的单个条目会被跳过并记录；tar 结构损坏的层标记为 `FAILED` 并记录原因，
其余层继续扫描，报告中逐层可见。
